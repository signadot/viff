# Residuals

What a landing named and did not build, kept so a known gap does not become an unknown one.

Each one is an issue now rather than a file. A gap wants a state and an owner, which is what a
tracker is for and what a note kept badly — the audit that produced this table found residuals
claiming "nothing here has been built since it was written" about work that had shipped. The
reasoning still travels: an issue carries the note's prose whole.

**A residual is a relation between one landed thing and one gap**, so a row says both: what the
gap is missing from, and where it is tracked. Nothing here owes coherence to the row above it.

## The convention

- **An id is a prefix.** `git issue show wzte` works; the table carries eight characters, which
  is unambiguous today and cheap to lengthen if it stops being.
- **`git issue list --label residual`** is this table without the relation. The relation is why
  the table exists.
- **A tracker other than this one is fine.** A row's reference may be a Linear key, a Notion
  page or a thread — whatever the owner of that work uses. What a row may not be is empty:
  a gap with no reference is a gap nobody can pick up.
- **Closing one is closing the issue.** The row goes when the gap does, and what was built lands
  in [done.md](done.md) like anything else.
