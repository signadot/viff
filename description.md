# verserunner: the brief says what reaches the world from a task, from the tools it was given

Staging test drive, 2026-10-20. A task told to "file an issue" spent 48 boundaries looking for a `git issue` binary in its shell, then trying to `go install` one, then reading `/proc`; a second told to "file an issue" with the tool named did it in one call. The brief a task gets (`repoBrief`) covers delivery alone: commit, trailers, `git-push`, `git-fetch`, and what the policy decides about a push. The tracker and Slack tools reach the model only as entries in its tool list, and nothing says that the shell has no command-line client for any of these systems, that nothing it installs can reach them since the runner holds the credentials, or that a refused call is an answer rather than a transient.

One paragraph, built from the tools left after `offered(tools, policy)`, since that is the only list that cannot lie: one line per system with its tools in the documents' order ("`github-issue-create`, `github-issue-comment`, `github-issue-close` (issues at the forge)"), then the two facts that hold for every performed system by construction: no client in the shell and nothing installed reaches them, the runner performs each call and the policy decides it; a call the policy refuses is a decision, said and stopped on. A task with no performed tools gets no paragraph. A test holds the brief to the offered list.
