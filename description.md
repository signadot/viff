# systems: a document's `date` is a label nothing cites

Daniel's Low 7 on PR #24. Each system document carries a `date`, the version of the system's verbs and params, and nothing names it: not a runner's offer, not a launch, not a task's record. So nothing says which version a runner implements, or which a policy was checked against.

An offer's `systems.<name>` should carry the date its code was checked against, a launch should carry the dates its rows were checked against, and the task record the same, so a runner whose code lags a document is named at registration rather than discovered at a task's call, and a record reads with the vocabulary it was written in.
