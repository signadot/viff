# verse.charter-get, charter-check: a task reads the charters and asks whether its own would install

The verse system's read-only charter verbs, as `verse charter` and verse_charter, verse_charter_check take them, ahead of install and remove (which come with a charter-level TTL).

- Tools `verse-charter-get` (path, at, depth, paths, if, trim) and `verse-charter-check` (at, charters), each typed as its MCP tool types it, and answering as it does: a charter as its file with the notes the file cannot say, a reach into one as it stands, a listing one kinded path per line; a check's verdicts and what an install would change.
- Carried as GET /charter and POST /charter/check, admitted at the door as the task's owner: relayedActs gain the two routes.
- What reads a charter tree as files, lists its paths, builds the read's query, and reads a text of charters moves out of cmd/verse into a package of its own (charterfile), so the CLI, verse mcp and the runner read and answer alike.
- Steps `verse.charter-get` and `verse.charter-check`, with no fields.
