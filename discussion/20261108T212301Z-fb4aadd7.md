**Four review findings to batch with this work** (from the stone-age review of the whole stack, 2026-11-08; they live on the lower branches — secret-exec and mcp — so fixing them means touching under the pkg stack, same as this issue's change; findings 1–5 of that review were pkg's and are fixed on `verse/pkg`):

1. **`filled()` re-parses a verb's default on every act decision** (`pkg/systems/document.go:585`). Every `Shape.Matches`/`Meets`/`ShapeWithin` call does a document lookup, and for a verb with a defaulted field (secret.exec's `env`) a full tony parse of the default string, per shape per check — on the hot path of every system's every act, not just secret.exec's. Precompute the default's pattern on `Field` at document load, and return early where the verb defaults nothing.

2. **`TakesTool` is triplicated** (`claude/claude.go:111`, `codex/codex.go:1102`, `verse/build.go:448`): the same 64-char bound, the same `^[a-zA-Z0-9_-]+$`, three near-identical functions. Drift here means an MCP tool offered to one doer and silently dropped from another. One shared helper, parameterized by the doer's word (and Claude's `mcp__verse__` prefix length).

3. **delivery's `streamed` map never shrinks** (`delivery/server.go:253`): one entry per streamed request id for the task's life; a long task looping secret-exec grows it without bound. Delete the id when the final answer is sent — send already holds the `writing` lock.

4. **`rights.take`'s diagnostic lies when the batch is long** (`delivery/protocol.go:316`): `len(batch) != N` reports "the channel read fewer" even when it read more descriptors than the frame claims. Say "read N, the frame claims M".
