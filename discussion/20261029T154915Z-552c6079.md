# Step matches are tony matches

A row's `match:`, an environment's shapes and a runner's ceiling all describe steps. They all
use one language: a **tony match over the step as a document**. This is the same `tony.Match`
a charter's `value:` and `verse data --if` already use. The old flat glob-string language goes
away. Simple rows read almost as they do today:

```tony
autonomy:
- {match: {system: git, verb: push, ref: refs/heads/main}, then: deny}
- {match: {system: git, verb: push, ref: !glob "refs/heads/verse/auto/*"}, then: allow}
- {match: {system: git, verb: push, force: true, own: false}, then: deny}
- {match: {system: commands, verb: run, command: !regexp "git push"}, then: deny}
- {match: {system: verse, verb: ask-create, on: !not.all.not {answer: null}}, then: deny}
- {match: {system: verse, verb: ask-create, on: !not.all.not {ask: null}}, then: deny}
- {match: {system: verse, verb: data-put, path: [scratch]}, then: allow}
- {match: {system: verse, verb: !or [data-put, data-rm]}, then: ask}
- {then: ask}
```

The two `verse.ask-create` rows refuse a raise if any choice answers another ask, or raises a
further ask. Together they mean the task's asks never answer an ask at any depth. A raise whose
choices only spawn is let through. The `data-put` row keeps writes under `scratch` unasked.
None of these can be said today.

## The step is a document

`task.Step` is `{Name, Doc *ir.Node}`, and the doc replaces `Fields map[string]string`. The doc
is flat:

- `system` and `verb`.
- The block's attributes (`repo`, `from`).
- The verb's fields, each typed by its form.

```tony
{system: git, verb: push, repo: github.com/acme/app, from: main,
 ref: refs/heads/verse/auto/x, delete: false, force: false, exists: true, own: true}
```

The runner builds the doc from the act it is about to carry out, as `delivery.s.refused` builds
`Fields` today. It never takes the doc from what the task says. A verb with structured input
carries that input in its parsed form:

- **`verse.ask-create`**: the `api.Ask` that `api.NewAsk` produces: `to` as a list, `labels` as
  an object, and `on` (below) as verse stores it.
- **`verse.data-*`**: `path` as the address's segment list, plus `value`/`on` for a put.
- **`verse.charter-*`**: the charters as `charterfile` reads them.

A system's document gives every field a form, and the form decides the value's type in the doc.
The forms today (`bool`, `ref`, `branch`, `repo`, `upper`, `lower`, `text`) give a bool or a
string, as now. Three forms are added:

- `int`, a tony integer. The network's `port`, which has no form today, takes it.
- `path`, an address (below).
- `doc`, structure held as given: an ask's `on`, a put's `value`, a charter.

**An ask's `on`.** The ask struct changes with this. `then` and `else` go, and `on` takes
their place: an object keyed by choice, each value one act.

```tony
on:
  yes: {spawn: {…}}
  no: {ask: {name: ship-lead, question: "…", to: [ann@example.com],
             on: {yes: {answer: {ask: ship-3f2a…, choice: proceed}}}}}
```

- A choice is one of the ask's options. Today those are `yes` and `no`; vfved3g6h12krt78w5n0
  gives an ask options of its own, and `on` is keyed by them.
- An act is `{spawn: …}`, `{answer: {ask, choice, say}}` or `{ask: …}`, one key, as `then` is
  today. A nested ask has its own `on`.
- `onSilence` names a choice, and silence at `due` runs that choice's act.
- A choice with no act is a vote on that choice.

`then`/`else` already mean "on `proceed`" and "on anything else" (`followField`), so this is the
same contract, spelled by choice. `api.Ask`, `verse ask`, `verse_ask_create`, the record, the
docket and asking.md change together, as one commit that lands before the match change.

For a row, `on` is a plain object, so tony's `!all` reaches each choice's act:
`on: !not.all.not {answer: null}` is "some choice answers". Nothing looks inside a spawn, so a
spawn's own `answer:` field (its answer contract) is never in the way. Depth is bounded by the
second row: a task whose asks may raise no further ask has nothing nested to look into. (`!any`
would read better than `!not.all.not`; it is a small addition to tony, not needed for this.)

`system` and `verb` are reserved. `systems.Check` refuses a document that has an
attribute or field with any of these names.

## What a match is

A row's match, with any `!let` expanded, is an object. It names `system` as a literal, and
`verb` as a literal or a pattern (`!or [data-put, data-rm]`). Every other key is a tony match
pattern for the doc's field of that name. Tony's object semantics cover what rows do today:

- Named fields must match.
- Other fields are ignored.
- An absent field fails a key that names it.
- `null` means the field is present, with any value.

**Address fields.** A top-level field of form `path` is read as a charter's `path:` is read. The
pattern is a list of segments, or a kinded path string (`demo.pr.*`). Each segment is a name,
`*`, or a tony operator over one segment (`!glob "hotfix-*"`). The step matches when its address
is at or under the pattern. This is the same address reading verse uses everywhere else
(`entity.Under`).

**Operators.** A step match is a `tony.Match` pattern, whole: every operator tony has,
`!let` and its `.[name]` bindings included. Verse defines no operators of its own and refuses
none. Tony already refuses a name no `!let` binds. A charter does not bind into a row's match at
a firing, as today.

**Globs and regexps.** `!glob` is Go's `path.Match`, and `!regexp` is Go's `regexp`. Both
are documented in Go, and neither changes. Each takes a part of today's flat pattern:

- Today's `*`, within a segment, is `!glob`'s `*`.
- Today's `**`, across segments, is a `!regexp` with a prefix: `refs/heads/verse/**` becomes
  `!regexp "^refs/heads/verse/"`.
- Today's `*` on a command, where `/` is just a character, is an unanchored `!regexp`:
  `*git push*` becomes `!regexp "git push"`, which matches anywhere in the command. That is
  the natural spelling for a command, and `^` or `$` anchors it where a row wants that.

Go's `!glob` also has `?`, `[…]` and `\`, which today's patterns read literally. A row that
means a literal `[` or `?` writes a literal string instead, or escapes it in the glob.

(tony's `!glob` calls `filepath.Match`, not `path.Match`. The two differ on Windows alone. That
is tony's to settle, and nothing here depends on it.)

## Ceilings and environments

A shape is a step match on one verb, minus `system`/`verb`, because the block names them. A
ceiling's attribute patterns are tony patterns too. One alternative is written `!or`, not a list:

```tony
ceiling:
- repo: !regexp "^github\\.com/signadot/"
  fetch: {}
  push: [{ref: !regexp "^refs/heads/verse/"}, {ref: !glob "refs/heads/release/*", force: false}]
```

```tony
network:
  ceiling:
  - mode: !or [none, allow]
```

An environment's attributes are still values, not patterns.

## Within, reaches, covers

`Autonomy.Within`, `Environment.Within`, `Ceiling.Contains` and `reaches` compare patterns with
patterns. They do so through two functions in `systems`. These functions analyze patterns: they
read any tony pattern, and they don't limit what a row may say.

- `Contains(outer, inner)` **under-approximates**. It answers true only when every doc that
  `inner` matches also matches `outer`.
- `Meets(a, b)` **over-approximates**. It answers false only when no doc can match both.

Rules for each operator:

| Pattern | `Contains` | `Meets` |
|---|---|---|
| Object | Every key of `outer` is in `inner`, contained key by key | Shared keys meet |
| `!glob` | Today's `PatternContains`, with `?` and `[…]` read conservatively | Today's `Intersect`, likewise |
| `!regexp` | A prefix regexp (`^` and a literal) contains a literal, a glob or a regexp that starts with that prefix; any other regexp only an identical one | A prefix regexp meets what could start with the prefix; any other is assumed to meet |
| `!or` | `outer`: any branch contains `inner`. `inner`: every branch is contained | Any branch meets |
| `!and` | `outer`: every branch contains `inner`. `inner`: any branch is contained | Every branch meets |
| `!not p` | `outer`: holds when `p` and `inner` cannot meet. `inner`: only when `outer` is `null` | Fails only when `p` contains the other side |
| `!let` | Read through its expansion | Read through its expansion |
| Any other operator (`!lt`, `!at`, `!subtree`, …) | Only against an identical pattern | Assumed to meet |
| `path` fields | Strata's `segContains`/`entity.Under` (moved from `trigger` to `entity`) | `segDisjoint`/`entity.Overlap` (moved likewise) |

Each answer leans toward refusing, so `Within` stays sound. An operator the analysis doesn't
model is still allowed in a row. Under a ceiling or an outer autonomy, it is held to the outer
row's mode unless the outer pattern is identical or `null`. Supporting another operator better
only makes `Within` refuse less. It never changes what a row means.

`covers`, `MayAsk` and `About` read `system` and `verb` as they do now, and match `verb` when it
is a pattern. `About` and refusals print a pattern in its tony form.

## What breaks, and how it is found

Every old pattern has an exact new spelling:

| Old pattern | New pattern |
|---|---|
| A bare string with `*` | `!glob` |
| `**` | `!regexp` with a `^` prefix |
| `*` on a text field | Unanchored `!regexp` |
| A ceiling attribute list | `!or` |
| `"false"`, `"443"` on bool/int fields | `false`, `443` |
| A literal `?`, `[` or `\` in a pattern | A literal string, or escaped in the glob |

`Check` keeps one rule: it refuses a pattern that can never match a value of the field's form
(`Field.Accepts`). It adds nothing on top of tony. Most old spellings now fall under that rule,
and the refusal names the new spelling:

- A bare `refs/heads/*` on a `ref`, `repo` or `branch` field is a literal no value can equal.
- `"false"` on a `bool` field is a string, and the field holds a bool.
- A list on a ceiling attribute is an array, and the attribute holds a scalar.

The rule reports these wherever a row is checked: at a spawn, at install, at
`verse task autonomy`, and in a runner's config.

Text fields are the exception. `command: "*git push*"` is a valid literal, and
`!glob "*git push*"` a valid glob that stops at `/`. Neither can be refused, so a row written the
old way on a command would match less. The one-time rewrite covers stored rows, and the commands
docs cover new ones.

Stored rows (installed charters' spawns, live task records, runner configs in the deploy repo)
are rewritten once by that mapping.
