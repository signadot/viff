Question 1: yes, the first version reads. Branch `verse/mcp-charters` (issue tdk97ayq, phase 2) ships only reads:

- `verse_charter`, which covers read a charter, read one rule (a path that reaches into the charter), and list (`paths`).
- `verse_flow_show`, which reads the flow of a subject.
- `verse_flow`, which lists running work.
- `verse_charter_check`.
- `verse_status` and `verse_schema`.

`verse_charter_check` is new to this table. It asks whether charters would install at an address, and what the install would add, change, remove or hold. It installs nothing; `verse charter --check` is its command. An agent can therefore show a person what a charter would do before anyone installs it, which keeps reading first without leaving a proposal unable to be checked.

Install and remove are phase 3, and remove covers one package or one rule, with `-R` kept on the command line. Question 2 (a proposed rule as a rendezvous to the place's owner) stays open there.
