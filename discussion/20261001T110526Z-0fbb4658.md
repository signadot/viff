Root cause of my previous comment's repro, fixed in 55e8c25c: the logd store kept only the last of two preconditions about one place. The frame post's `[notStatus(answered), notStatus(orphaned)]` therefore went to logd as "not orphaned" alone and was admitted over an answer every time. `settlePending` had the same defect, so a settling could turn `answered` into `orphaned`.

That changes what this issue says. The "precondition evaluated against a view that lags the answer" in 7b6cb09d's discussion, and in the code comments, was measured while the guard was broken. Admitting the write needed no lag. Whether two concurrent writers leave any window now that the guard holds has not been measured. The comments in mirror/question.go now say exactly that.
