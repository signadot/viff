Review round 4, fixed in **4576dea4** on verse/claude-runner (local, unpushed; the PR is still held behind Daniel's runner/... PR). Two fresh reviewers looked at the code: one at the wire (protocol, concurrency), one at the driver (semantics against the task loop). Each fix below has a test that fails when the fix alone is disabled (19 mutants).

**Fixed, most severe first**
1. **The gated path is the written path.**
   - Before: a relative Edit/Write path was clamped into the workspace for the gate, while Claude resolved it against its cwd. `../../src/x` was gated as `src/x`, and absolute paths outside the workspace, or through a symlink, were gated as written. Round 3's path cleaning introduced the clamp.
   - Now: a path that leaves the workspace is refused before the gate, by `agent.SafePath` (the verse agent's check, now exported).
2. **A late say is a turn of its own.**
   - Before: a say that reached Claude as its turn ended was lost; the run ended on the old result, and Close killed the new turn.
   - Now: `--replay-user-messages`, and a result ends the turn only when every sent message has been echoed.
   - Probed on 2.1.304 (the pinned version) and 2.1.305: a message sent at a tool boundary is echoed after the tool_result, inside the running turn; one sent during plain text is echoed as the start of the next turn.
3. **No wait on a request Claude gave up:**
   - a cancelled queued request is skipped;
   - Execute allows nothing for a request already cancelled;
   - a question taken back mid-ask leaves the docket;
   - every open request is cancelled when the stream ends, so a gate question goes with a dead Claude;
   - `awaitCall` ends on the use's own result when no tools/call comes;
   - Control ends on the stream's end;
   - an undecodable control_response still reaches its caller.
4. **Every request is answered:**
   - a line with a mistyped field is still refused;
   - an unknown subtype gets `subtype:error`, not success;
   - an MCP notification is acknowledged as `{mcp_response:{jsonrpc,result:{}}}`, the Python SDK's shape.
5. **The multiSelect hint was filing the answer under altered text** (my round-3 fix). The hint now goes on the docket only.
6. **Smaller fixes:**
   - AskUserQuestion is offered only where the policy provides `question.ask`;
   - a read outside the workspace and a background Bash are refused with a message the model can act on;
   - `with.effort` accepts only `low|medium|high|xhigh|max`;
   - a null input is sent back as `{}`;
   - Close doesn't take the write lock, so a wedged write can't block the kill;
   - the proposal is atomic (the supervisor reads it on the gate goroutine);
   - cancel channels are let go once a request is answered.
7. **Docs:**
   - runnerd.md's Claude section: workspace bounds, free reads, when CLAUDE_CONFIG_DIR is private, late says;
   - the codex row for questions now names `question.ask`;
   - question.md.

**Declined, with reasons**
- Matching `tools/call` by name when `_meta` is missing: the version is pinned and the meta was seen on staging. Fix 3 already ends the wait when Claude fails the call.
- Killing Claude's process group on Close: the task's bwrap `--unshare-pid --die-with-parent` reaps children when the task ends.
- Bounding `initialize`, and serving MCP during it: speculative against the pinned version, which answers it at once.
- Parallel read-only Bash deadlock: the earlier probe saw Claude ask sequentially.
- Converse on the claude offer: out of scope.
- A 64 MiB line ends the stream with a clear error. Practically unreachable; no change.
