**Update to the review-github contract: it sends through a declared outbox** (84a83gkw, as proposed there on 2026-10-01). This replaces "depends on sinks".

- review-github keeps its requests to GitHub inside its own address, in an outbox it declares: `sends: [{from: out.github, to: github.<org>.<name>.out}]`. That is one io per entry, and the github io admits review-github's address on its side (proposed).
- **Its statuses are readable again.** The io writes `~status` beside each request in review-github's own place. So the open request's status can say which PR it opened or adopted (`number`), and review-github can derive `review.<repo>."<branch>"` from that. Reading the PR reflection keyed by branch also still works.
- **A merge request's outcome is readable** from its status as well as from the reflection.
- The open question "fields on the proposal record, or separate request entities" reopens, because separate requests now each get a readable status, as io inputs do.

Everything else in the draft contract stands: the places and their writers, the ask surfaced by a rule like gate-ask-channel, the io rendering `asks`, comment-command answers, and the mirrored PR review.
