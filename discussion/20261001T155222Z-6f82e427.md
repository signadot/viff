Declared outboxes are built on `verse/declared-outboxes` (off main 8311e8d5), commit 2c8b1167. Not merged.

- **Declaration.** `sends: [{from, to}]` beside `reads:`, recorded on the package's record (`verse.trigger.package.<at>`). It is parsed from the same fielded charter in the same install step, and undone with it when the file is refused.
- **Install checks.** `from` is read against the package's address. `to` must be an out place a registered io reads. One `from` feeds one io. `sends:` needs an address.
- **Grants.** These mirror seedOut, at the outbox: the installer takes the place, and the io's `as` gets read below it and child-owner. They are taken back when the entry or the package goes.
- **The out half.** It reads its own place, then each outbox from `GET /outboxes?to=<place>`, which is answered only to that io's `as`. An outbox input is handed to the sink as asked at the io's place (`Input.Place`), and its status lands beside it, inside the package.
- **No io-side consent,** as decided.
- **`verse c`** lists `sends:` relative, as written.

Tests: `versed/outbox_test.go` and `io/outbox_test.go`, the latter running a real out half end to end. Seven mutations, one per guard, each fail a test.

**Still open, from "Done when":** moving `gate-ask`, `deploy-announce` and the digest out of baseline into packages that declare outboxes. That change is to the deployment charters, and it needs the branch merged and deployed first.

**Not covered:** an io removed while packages still name its place in `sends:`. The listing stops, but the outbox grants stand until the package is re-installed or removed. A re-install then refuses, because `to` is no longer an io's out place.
