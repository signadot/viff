Decisions while doing step 2 (2026-10-23):

- **Decision 3, refined.** Only versed's private runner record moved into `api`, as `api.Runner`. `io.Entity` is built from `io.Own`, `io.OutHalf` and `io.Failure`, which the connectors use as their contract, and `io` already imports `api`, so moving it would have touched every connector. Moving `resolver.Resolver` would have made `api` import `trigger`. So both records stay in their own packages, with their rows beside them (`io.Row`, `resolver.Row`, …), and both packages are now generated and folded into the schema.
- **Asks deferred to step 3's PR.** The stored ask fields are a string or a list depending on how they were written (`waitingOn`, `about`, `answerers`). Typing them in step 2 would have meant changing how asks are stored, and step 2 promised no wire change.
- **The `runner/doc.go` test moves to step 3.** The two runtimes still differ (routes registered without a method, 404 vs 410), so a test now would only pin drift that step 3 removes.
- **Decision 4, new: a GET by name keeps answering the record.** Making it answer the listing row would break `verse iod show | verse iod add`, a round trip `io.Entity`'s own comment protects, because `add` refuses unknown fields like `at`. A create still answers the row its list shows in step 3.
