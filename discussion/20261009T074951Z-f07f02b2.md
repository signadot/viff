Built, on `verse/codex` in `.worktrees/codex`: commit 269522b1, one commit on main 3f2f5fd5. Not pushed.

**What is there**

- `coderunner/codexrpc.go`: the wire. Starts `<bin> app-server`, frames JSON-RPC over stdio one object per line, routes answers to callers and queues codex's requests and notifications in order through an unbounded queue, so a burst cannot stall the reader that also delivers answers. The only file that knows the format; on the json allowlist.
- `coderunner/codex.go`: the driver. `Next` waits on codex and returns each approval request as a `ToolUse` with derived effects (`shell` → exec, plus network when the command wants a host; `apply_patch` → create/write/delete per path from the item codex started, relative to the workspace; `ask` → question; `request_permissions` → network and read/write on the paths named). `Execute` answers `accept` and waits for the item to complete, so the exec frame carries the output and exit code; a blocked gate answers `decline` and says why through `turn/steer`. Agent messages are `say` frames; commands and patches codex ran without asking are `exec` frames when they complete. `Fold` mid-turn is `turn/steer`, between turns the next `turn/start`. Ctx end interrupts the turn; the run's end closes the process (new `task.Closer` capability, called by `Run`).
- Config: a `codex:` section (`bin`, `model`, `sandbox`, `apiKeyEnv`, `config` overrides); `driver: codex` is a builtin. Refused at load for an environment naming it with no section, and at spawn likewise. The key is resolved by the parent and travels to the task process with the LLM creds; it reaches the codex process's environment only.
- The thread is started with `approvalPolicy: untrusted`, `approvalsReviewer: user`, `ephemeral: true`; the frame goes to `developerInstructions`; the answer contract rides the opening prompt.

**Tests** (`codex_test.go`, a stand-in app-server that is this test binary re-executed): a gated command approved from the docket with its output on the exec frame; a patch denied with the decline and the reason reaching codex; the model's question on the docket with codex's options, answered by one and read back by codex; a steer landing as `turn/steer` on the active turn and a later one starting the next turn; cancel as `turn/interrupt`; a failed turn failing the run with codex's message; a missing binary; effect derivation; the default vector; config checks. `go test ./task/... ./docs/reference/examples/coderunner/` and `make check` are green.

**Checked against the real binary** (codex-cli 0.162.0, installed in a scratch dir): `initialize` and `thread/start` with these params answer as the driver expects; the protocol schema used for the message shapes was generated by that binary. A turn was not run: it needs an OpenAI key or login, and the machine had neither. So approvals, steer and item streams against the real codex are the next thing to exercise, and the first place a field name could differ from the stand-in.

**Not done, by design here**: codex's trusted read-only commands and its web search run without asking and are narrated, not gated (stated in the README and the source). Codex's own sub-agents (collab tool calls) are not mapped to children. `acceptForSession` is never answered, so codex asks every time.
