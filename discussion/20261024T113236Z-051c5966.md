**Head**
- `at: signadot.stale-review`, `reads: [github, verse.schedule]`.
- `schedules: [{name: morning, every: 24h, from: <RFC3339, 09:00 on a weekday>}]`. A whole-day period steps by calendar day in the daemon's zone, which is `TZ`; nothing sets it on staging, so the hour is UTC. The README says so.
- `sends: [{from: out.slack, to: slack.Signadot.out}]`. A confined charter writes only inside its address (trigger/confine.go:178), so the DM goes through an outbox the install forwards, as deploy-announce.tony does; gate-ask writes to the out place directly only because it is the unconfined system charter.
- Strata, per package (levels need not avoid other packages'): `reflected` 0 over `github.signadot.signadot.pr` (a derive's `!list-paths` read must resolve at or below the rule, stratum.go:804); `ticks` 5 over `verse.schedule."signadot.stale-review:morning".tick` (a rule that derives must be in a stratum owning its subject, stratum.go:782); `day` 10 over `signadot.stale-review.day`; `outbox` 20 over `signadot.stale-review.out.slack`.

**Rules**
1. `gather`, stratum `ticks`, on `verse.schedule."signadot.stale-review:morning".tick.*` with `value: {weekday: !not.or [Sat, Sun]}` (the tick's weekday is three letters; tags compose with a dot): derive `signadot.stale-review.day` with `id: $subject.value.date` and `prs: !list-paths {at: "github.signadot.signadot.pr.*", value: {state: open, requestedReviewers: !subtree <login>}, path: number}`. `!subtree` dives array elements and matches a string by equality (verified with `o match`); a plain `[login]` would not, since an array pattern is positional. A tick needs no latch; a missed tick after an outage fires once with the due instant's weekday.
2. `review`, stratum `day`, on `signadot.stale-review.day.*` with `value: !and [{prs: !not []}, !not {stage: null}]` (absence is the latch form latch.go names): spawn on `verse.runners.claude`, `agent: {name: claude}`.
   - Environment: `git: [{repo: example/app, from: master}]` (the checkout the read verb needs until z85vx3z2; no fetch, no push), `github: [{repo: example/app, read-pr: {}}]` (no `list-prs`: the iod supplies the set), `network: {mode: none}` (Claude's API is reachable whatever the task's network). Within the staging ceiling once `read-pr` exists; the file cannot install before z05vx3z2 lands.
   - Autonomy: allow `github.read-pr`; deny the rest.
   - Prompt: the login, the threshold, `$prs`. Staleness from what `read-pr` answers: GitHub does not say when a review was requested, so a pull request is stale when the login is in `requestedReviewers` (which already means waiting on them, yw5vx3z2) and its `updatedAt` is over a day old, and no review by the login was submitted after that. The answer is a JSON block with every string quoted (docs/reference/tasks.md:71 names the unquoted-prose trap; comment-drift's prompt is the model).
   - Answer contract: `{stale: !irtype [], digest: !irtype ""}`.
   - `onDone` patches `stage: done, stale: $data.stale, digest: $data.digest`; `onFailed` patches `stage: failed, err: $err`; `onCancelled` removes `stage`.
3. `notify`, stratum `day`, on `signadot.stale-review.day.*` with `value: {stage: done, stale: !not []}`: derive `signadot.stale-review.out.slack` with `id: $subject.name` and `{to: user:<email>, text: $subject.value.digest}`. A quiet day writes nothing (the Sink refuses `text: ""` permanently, so an unconditional hook derive would leave a failed status every quiet day). The target is in the value, `to`, as the Sink reads it; `asks` is optional; a bare-text DM to `user:<email>` is resolved by `users.lookupByEmail`. Keyed by date, level-triggered: a re-fire edits rather than repeats.
