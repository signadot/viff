Second review of phase 2: 3a97505d on verse/mcp-charters (local, unpushed).

Fixes:

- **Notes as their own block.** `verse_charter` returns the charter's notes as a second content block, so the first block stays the file and parses (including with `-o json`).
- **Flow refusals in the tool's own words.** `verse_flow` refuses a task combined with charter, subject or recursive, and recursive without a charter. The server's refusals for these name CLI flags.
- **Schema names.** `verse_schema` accepts only a definition name (letters, digits, `.`, `_`, `-`, starting with a letter or digit), so `?`, `#`, `%` and `..` can't reach the URL.
- **why-not.** It refuses a charter or rule that selects more than one, and quotes the subject in the `if` pattern for `verse_question`.
- **Spelling of notes.** Steps vs kinded paths is now a `spelling` value passed down, replacing the bool that sat next to `color`.
- **printCharter.** It reads the output format before the request, so a bad format no longer leaves a response body open.
- **oneDocument's refusal** now lists `sends:` among a charter's keys.
- **`--check -f`.** charter.md and the flag's help say it is checked as a directory holding that one file, prune included. The server's check always prunes, so the check describes `-a -d --prune`, not `-a -f`.

Not changed, because they aren't defects:

- `--check` with neither -d nor -f reads stdin, as `-a` does.
- The prompts read a charter by its full path without `at`, which resolves correctly. `at` is only needed to reach into a charter whose address is shadowed.

Each fix has a test that fails with the fix disabled, including a new pin of the CLI's steps spelling in the notes. make check, the suite and smoke (67) are green.
