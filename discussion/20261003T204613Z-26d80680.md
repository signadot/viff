**Decided: the git io is the doer** (2026-10-03). The writes this charter needs in git, the tag `live-verse.N` and moving `verse/live`, are made by the git io's out half: inputs under the repository's out place such as `{to: tag.live-verse.3, sha}` and `{to: branch.verse/live, sha}`, each with a status beside it, pushed with the credential the io already fetches with. Not the github io: GitHub's refs API could do it as the App, but only for repositories on GitHub, and the App has no clone to compute a tree hash from. The git io matches the rest of the design, where a system verse does not own is reached through its io, and it keeps the flow host-independent, which the git-only local leg needs.

Also decided (same day): the git io reflects the tree hash of a configured directory per ref, so "main's charters tree" is a field a condition compares; approval keys on that hash. Both are being implemented.
