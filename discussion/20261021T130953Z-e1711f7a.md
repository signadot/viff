Decisions for 6b (2026-10-21, after a Fable review):

- **The physical limit is `builds`, not `supports`:** `systems.<name>: {builds: <blocks>, ceiling: <blocks>}`.
  - Today it only says the network's modes, derived from the sandbox and never written in config. An absent `builds` is the whole document.
  - A ceiling naming a mode the sandbox can't build is refused when the runner starts; this replaces the earlier "log only". So the published ceiling is the effective bound, and for the network an absent ceiling means `builds`.
- **An agent is `name` plus settings declared per offer.** The spawn writes them flat beside `name`: `agent: {name: codex, model: x, effort: high}`.
  - `name` and `annotations` are reserved, and an offer declaring a setting by either name is refused.
  - Each setting is typed: `{form: string|number|bool, values: [patterns]?}`. Values are strings on the wire, so `$` binding is unchanged, and the runner coerces them by form.
  - A setting the offer doesn't declare is refused.
  - Each setting says whether the agent has a private default. The record says which settings ran, defaults included.
  - `model` is reserved as the setting verse reads (for the record, and later for cost).
  - The offer's settings already include the operator's narrowing, written in the runner config. There is no separate settings ceiling.
  - Annotations stay separate: plumbing verse or the runner writes, not knobs for authors.
- **Removed:** `with` and `Accepts`.
- **Default agent:** the first agent offer is the default, and `Runner.defaultAgent` reads it from `Describe`.
- **Schema version:** `Description` gains one. A stored registration whose offer is stale (an older version, or a ceiling that fails `Check`) is refused with a reason, not misjudged. Runners are re-checked after deploying.
