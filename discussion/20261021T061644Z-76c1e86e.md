**ffe43fb9** replaces round 4's write containment (4576dea4), after discussion with Scott: the workspace is the task's filesystem, and bwrap bounds where a write can land.

**The change**
- **Two paths decide a write.** An Edit or Write is decided on the path Claude names. Where symlinks lead it to another file of the workspace, it is decided on that file too, so a row on `db/**` decides a write through `docs/link → ../db`.
  - Chains are followed to the end.
  - A last link that names a file not there yet is followed too, since the write creates it.
  - A link out of the workspace adds no step.
- **The outside-workspace refusal is gone.** Under bwrap, everything outside the workspace is read-only system dirs, the task's own `/tmp`, or absent.
- **`agent.SafePath` is unexported again.** The verse agent's package is byte-identical to fcfff61e, so there's no conflict surface with Daniel's runner PR.
- **Relative paths:** joined to the workspace, not clamped into it.

**Probed against 2.1.304 locally (haiku):**
- **Claude's own rules check two paths:** the path as named and the fully resolved target. A deny on either one denies, an allow without asking needs both, and the hops in between are not checked.
- **The `can_use_tool` request carries only the named path,** absolute and lexically cleaned. It has no target and no `blocked_path`; the other fields are `display_name`, `description` and `permission_suggestions`. So the resolving has to happen on our side.
- **Under the runner's exact settings,** every write asked this side, with nothing settled inside Claude: a plain path, a path through a link, `../outside`, `/etc/x`, `.git/x`, `.claude/settings.json`.

**Open, not changed here:** `stepOf` decides a multi-step request by the first step that a non-allow, non-default row names. So `docs/**: allow` with a default of `ask` allows a write through `docs/link → other/`, where Claude's own rules would ask. A deny or ask row on the target still decides. Codex's multi-file patches work the same way. Making an allow cover every step would change policy semantics for both agents, so it belongs in its own issue if wanted.
