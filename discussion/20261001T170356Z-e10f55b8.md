# Design: declared outboxes

This supersedes the sink proposal in the description, which is kept there as the option considered and not taken. Built on `verse/declared-outboxes`: 2c8b1167 and e8060e89.

## The problem

A package writes only inside its address (`trigger/confine.go`), and an io's out half reads only inside its claim. The two never meet, so every rule that asks an io to act has been baseline's: gate-ask, deploy-announce, the digest.

## The design

A package declares its outboxes beside `reads:`:

```tony
at: acme.announce
sends:
- from: out.slack                # a place inside this package's address
  to: slack.example.out         # an io's out place, as its registration names it
```

- **An outbox is a place inside the package that an io reads**, as it reads its own out place. It is an outbox only because its package declares it, so the existence of an io gives no package's values a meaning the package did not declare.
- **One io per entry:** a `from` feeds exactly one `to`.
- **No io-side consent.** The io does nothing to opt in; consent on its side can be added later.
- **The engine is unchanged.** The package's writes stay in its address and its own strata, so there is no sink exemption and no level exception.

## What the install does

- **It checks:**
  - `from` is read against the package's address;
  - `to` is an out place some registered io reads;
  - a `from` is not sent twice;
  - `sends:` belongs to a charter with an address.
- **It records** the outboxes on the package's record (`verse.trigger.package.<at>`) beside `reads`, from the same document and in the same step. They are undone with the rest of a refused file.
- **It holds the outbox out to the io,** as seedOut holds out its own place: the installer takes the outbox, and the io's `as` gets `read` below it and `child-owner`. The io may read what is asked there and own each status it writes, and nothing else in the package. The package's rules ask as its installer, who owns the place already.

## The grant follows both sides

It stands while the package declares the outbox and an io reads the place it sends to.
- Re-installing the package without the entry, or removing the package, takes it back.
- Removing the io takes back every outbox grant sending to its places, whether the removal said `--forget` or `--keep`.
- Installing the io again grants the outboxes still declared for its places.

## The out half

- **Each pass,** it reads its own place, then each outbox from `GET /outboxes?to=<place>`. Only that io's `as` (or the system) may list; anybody else gets `403`, and a place no io reads gets `404`.
- **An outbox input** is handed to the connector as asked at the io's own place (`Input.Place`), so a connector serving several places treats it the same.
- **Its status** is written beside it, inside the package, so the package's rules can read what became of it. That was the cost the sink proposal accepted.

## Listing

`verse c` prints `sends:` with `from` relative, as written, so a printed charter installs back.
