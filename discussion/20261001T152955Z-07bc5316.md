**Proposed alternative to sinks: declared outboxes, opt in on both sides.** (Discussion, 2026-10-01.)

Rather than every package writing into an io's out place (a sink exempt from confinement and from the level check), each package keeps its requests inside its own address and declares which of its places is an outbox for which io:

```tony
at: acme.announce
reads: [git.verse]
sends:
- from: out.slack                # a place inside this package's own address
  to: slack.example.out         # an io out place, as the io's registration names it
```

- **Install checks it.** `from` is inside the package's address, and `to` is an out place a registered io claims; otherwise the install is refused, naming the part that is wrong. **One io per entry (decided):** a `from` feeds exactly one `to`, the simplest thing to audit.
- **It grants the io that place and nothing else:** read on the outbox, and write on its `~status` names.
- **The io's input set is its own claim plus the declared outboxes that target it,** obtained from verse, which knows the installed packages. It is not found by walking for a naming convention. Removing the package or the entry ends it on the io's next pass.
- **No meaning is forced on a package's values by an io existing:** a place is an outbox only because its package says so.

Compared with sinks:
- **Confinement and strata stay as they are.** Writes stay in the package's address and its own strata, so there is no exemption and no level exception.
- **A package can read its own sends.** The `~status` lands inside its own place. That removes the cost the sink proposal accepted ("a package cannot read its own sends").
- **Who asked is in the address,** which the prefix rule wanted, without a prefix rule.

**Proposed, not decided: consent on the io's side too.** The io's registration says which package addresses may send through it, so an io's operator decides who can make it speak. This is the same two-sided consent as a resolver grant.

Unchanged from the proposal above: `gate-ask`, `deploy-announce` and the digest would move out of baseline into packages that declare their outboxes.

Not the route: derived views (built on `verse/derived-views`, unmerged). They make a read track; they do not let a package's writes reach an io.
