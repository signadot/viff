The two open questions, answered by what the code already did for the other two cases:

- **Per-launch, not the vector's.** An ask's `then` (versed/asks.go) and a rule's spawn `as: subject` (versed/server.go, spawnerFor) both put `[$principal]` on `Launch.Answerers` and on the record's `answerers`, and `hostedQuestion` fills a gate naming nobody from the launch. The hand-run spawn computed `actsFor` for the `$principal` check and then did not use it. It now sets the same two fields when `actsFor` is somebody. The vector is untouched: a gate that names `answerers` stands over the launch's, as before.
- **`agent:*` drops out.** With `[$principal]` the audience is one principal: the person, or the agent that ran it as itself. A runner acting as itself (`runner:*`) and the system act for nobody (mirror.ActsFor), so their runs' gates stay the docket's, `user:*` and `agent:*` as now. Somebody else answers a person's run as a resolver they granted, or by being named on the gate.
