Direction on merge-is-decision (discussion 2026-10-01).

Verse does not take on code review itself: line comments and review threads in the style of Gerrit or GitHub PRs. Once that is conceded, the shape is:

- verse **creates the review environment** for a proposed change (for charters, together with a trial scope whose report goes into it);
- verse **determines when the environment is ready to merge**, and merges.

The merge is therefore verse's decision, made at the dial and on the record. Main is the record of that decision, and "keep main installed" installs the record.

**Gerrit** is a good contender and a good fit here. It is mature and active (3.14.4, 2026-09-23), and it keeps changes, patchsets, comments and votes in git refs (NoteDb), so a veto is a vote readable from refs.

**The review instance is abstracted per repository.** An open source project brings its own review instance: Gerrit, GitHub PRs, a mailing list, and others. Review environments are therefore supported through ios, in a plugin-like way: one io per kind of review instance. Each io creates the environment, reflects its state, and carries the merge. The system charter for repo charters speaks only to the abstract review environment. Adding or changing a repository's review instance is an io and a configuration choice, and it does not disrupt the system charter's flow.

Still open, from the discussion:

- what "ready" reads. The proposal is `ready = what verse knows (trial reported, checks green, window elapsed) ∧ no spoken veto`: review activity counts only as a veto and never as an approval, which is proceed-on-silence with a spoken deny. Whether a veto is read from the review instance (Gerrit vote, "request changes") or only from verse's own gate is not decided;
- verse being the only writer of main's `.verse/charters/` (branch protection or a ruleset), so that main is a record and not a side door;
- the shape of the abstract review environment, which the ios fill: create, the state reflected, merge.
