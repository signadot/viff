**Next tool: `fetch`.** The agent can only reach upstream by accident today: the clone's `origin` has the real URL and no credential, so `git fetch origin` works for a public repository on the egress allowlist and fails for a private one, and nothing gates it either way. The mirror, which is fetched at every spawn, stays on the parent's side of the hop, so `refs/remotes/mirror/*` in the clone is frozen at spawn.

The agent needs a fetch for a base that moved under a long task, for a destination that must fast-forward (`main` for the merge task), and to see a sibling's delivery.

Shape: a `fetch` tool beside `push`, over the same parent/child channel. Not `pull`: merging or rebasing is the agent's own git in its own checkout. The tool names a repository (and optionally a ref). The parent refreshes the mirror with the credential it already holds, then updates the clone's `refs/remotes/mirror/*` from the mirror, the same copy it makes at open. The agent then rebases onto `mirror/main` or reads what it wants. No credential crosses.

Gating: a `network` effect on the repository's URL, so the default codex vector asks and a charter that trusts reads leaves it to auto. Offered through the same tool floor as `push`, to codex and the harness alike. Nothing on the verse-facing runner interface.
