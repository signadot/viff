The discussion of this protocol needs to address several things

1. the decision to run the tool is in the loop rather than a normal tool call.
2. it disallows the agent to make decisions of what state it leaves behind after
the tool call in a natural way: eg push what's committed and use uncommitted or unstaged
files to do something else.
3. following the pattern of today, more tools would be added and coordinate parent-child relations, so it looks like could benefit from being generalized.
