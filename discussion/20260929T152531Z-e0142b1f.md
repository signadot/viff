Stage 8, Slack, decided: slack-io stays as it is, with asks under the hood.

- **Reading.** The out half reads the asks in a message to a person *as that person* (`Sink.As`, the controller's client factory), because only the ask's audience reads a person's ask. A message to a channel is still read as `agent:slack-io`.
- **Who is reached.** `gate-ask.tony` is installed at start as the system (deploy's `systemCharter`, i.e. `VERSE_SYSTEM_CHARTER` mounted from a ConfigMap), because a rule acts as its installer and only the system sees every ask put to a person. It has two rules with disjoint conditions:
  - `gate-ask`: a rule's question (non-empty `origin`); the line names the rule.
  - `gate-ask-person`: a person's ask (`asker`, empty `origin`); the line names the asker.
  
  A restart takes over the rule a person installed earlier; I checked this against a store where it was installed as a user.
- **Provisional `then` (A).** The DM shows who asked and what a yes runs, and a reply carries the edit the message shows. A reply to words changed since is refused. A message is remembered only once Slack shows it, so a failed redraw leaves replies tied to the old edit.
- **Served.** A DM for an ask your resolver serves says so, and `force <option>` answers it yourself. An answer through a resolver is drawn `via` it.
- **Turns.** Under an ask that takes `reply`, any words in the thread are the reply.
