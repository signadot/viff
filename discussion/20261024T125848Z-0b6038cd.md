Cause found, and fixed in 73cb4ecfd. It was neither of the two guesses in the description: the claude agent does report the error, and the task does record it.

The task recorded its cause, then emitted its terminal frame without it. The mirror reads `err` off that frame first. When the frame has none, it reads the runner's snapshot. In the window between the frame and `Run` returning, that snapshot still said running. It carried the result, read live, but not `err`, which was copied only after `Run` returned. So the entity got `result` and no `err`.

Fix: the three places that emit a terminal status (teardown, the loop with nothing to wait for, and the panic path) now put the task's `err` on the frame. The in-process snapshot reads `err` live. This applies to every runner and agent, not only claude.
