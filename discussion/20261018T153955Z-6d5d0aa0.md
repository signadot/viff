**Decided (2026-10-18): the network is a fact of the launch, and an offer's systems are what it intercepts.** Landed as 39bcaba1 on verse/cut (local, unpushed).

- `doer.with.network: {mode: none | open | allow, allow: [host[:port]]}`; absent is none. Built once when the run starts; no row decides a connection.
- An offer advertises `with.network` as the modes its sandbox builds: bwrap all three, an unconfined runner (`verse up`'s, `-sandbox none`) only `open`, so a launch there that leaves the network out is refused.
- The `network` system and `network.tcp-client` are gone; `holds` (policed/provisioned/none) is gone from offers and `held` from the task record. Every system offered is intercepted.
- An agent still reaches its model under none/allow (AgentHosts).

Consequences to keep in view:
- The operator's `systems.network` ceiling went with the system: a runner can no longer narrow the hosts its tasks may name. If that is wanted back, it belongs as runner config over `with.network` (e.g. which modes, which hosts `allow` may list), not as a system.
- A bare `InProcessHandler` with no offers described refuses only a named non-open network; absent is refused through the offer, which `verse up` always describes.
- A codex permission request that asks only for the network is gated as a write (the existing "nothing this side can name" rule), not granted outright.
