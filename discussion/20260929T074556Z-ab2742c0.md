**Decided (2026-09-29), stage 2:**
- Edits apply only to a person's ask. Nobody can edit a rule's gate or a task's question, so they carry no edit number.
- The field is `edit`: it clashed as `revision` with the store's revisions.
- A settled rule gate that fires again is a new ask with a new id. A firing is not an edit.
- By default, an answer that names no `edit` is counted against the current one. A door that shows the ask sends the `edit` it showed, and a stale one is refused.

**Stage 4's Q1 and Q2, answered from the model** (they didn't need stopping):
- **Q1: a person's resolver and a place's never overlap.** An ask goes to the parties it names, through their resolvers. Only an ask that names nobody goes to the resolver of what it's about. So a place's match applies only to asks that name no party, and can't overlap a person's.
- **Q2: declaring a match is the grant to answer for.** You declare a match for yourself (asks put to you) or for a place you own (asks about it), as a source's installer must own the slice it claims. Nobody can take somebody else's match first.
