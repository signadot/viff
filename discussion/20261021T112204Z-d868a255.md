Phase 1 of the surface is built on `verse/mcp` (tdk97ayq; commits 0324114a, 3c7a67c8, a8e12dee, local). The tools are named after the command each mirrors. Each tool that writes is a separate tool.

**Names**

| This issue | Tool |
|---|---|
| read one record, list | `verse_data` (`paths`, `depth` for the listing) |
| my questions | `verse_question` |
| answer | `verse_question_answer` |
| raise | `verse_ask_create` (question, to, due, then, else as separate parameters) |
| change my ask | `verse_ask_change`, `verse_ask_withdraw` (and `verse_ask` to read them) |
| say, pause, resume, cancel | `verse_flow_say`, `verse_flow_suspend`, `verse_flow_resume`, `verse_flow_cancel`, each on one `task`, as `verse flow <verb> --task` |
| wait | `verse_wait` |

Phase 1 also has `verse_task`, `verse_task_events`, `verse_task_run` and `verse_task_policy`. The verbs on one task are spelt under flow, so that phase 3 can take a whole flow.

**The shape of the wait**

The server holds the watch, not the call. `verse_wait` opens one watch on its first call: your asks, and the questions waiting on you, as `verse ask --watch` and `verse question --watch` print them. It follows that watch for the server's life and numbers the lines it says in a log of 1024. A call answers the lines after `since`, at once if there are any, otherwise at the next one. Every answer carries a cursor. Nothing between two calls is missed or said twice. This is because the watch's copy of each ask stays in the server, and a revision passed back could not carry that copy. A cursor older than the log is refused, with how to catch up.

**Two departures from the rules above**

- Rule 5: a call waits for at most `timeout`, which is 300 s by default and capped at 3600 s. It answers "nothing" and the same cursor when that runs out. The watch itself never stops. Only the call ends, and the next call from the cursor misses nothing. A host that cancels a call ends it at once.
- Rule 3: a read longer than an answer (64 KiB) is refused, never cut, with what to narrow. A transcript (`verse_task_events`) is answered in parts that each end at a frame, read on from the cursor.
