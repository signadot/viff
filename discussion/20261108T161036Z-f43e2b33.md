**Dead end, 2026-11-08. Superseded by 2k5art3x.** This plan binds each nix store path as its own
read-only mount, so installing a tool while a task runs means adding a mount to a running sandbox,
which needs `CAP_SYS_ADMIN` in the task's user namespace. Two staging measurements (step 0b and
0c, attached to 2k5art3x as `FINDING-0b.md` and `FINDING-0c.md`, scripts under `stone-age/`)
closed that off:

- **0b:** the runner cannot enter a bwrap-made sandbox's namespaces with capabilities — bwrap
  creates the user namespace in a forked child, so the runner enters with `CapEff 0` and cannot
  join the mount namespace.
- **0c:** even when the runner builds the namespace itself, a non-root uid loses every capability
  on `execve`, so an exec'd helper cannot mount; a root-in-userns map restores the helper's caps
  but equally privileges the task. The only form that keeps the task unprivileged is a resident
  privileged C namespace-bootstrap in every sandbox (runc/bwrap class), a security-critical
  addition to the trusted base. Rejected.

The per-store-path binding was the only thing forcing a runtime mount. 2k5art3x drops nix from the
framework: a runner installs tools into a per-task read-only prefix (`$I/{bin,opt}`) bound once at
start, and installs by writing files the task sees through the bind — no mount, no capability
(proven, `p11-robind.sh`). A concrete dynamic-library discipline (versioned cellar prefixes,
`DT_RUNPATH = $ORIGIN/../lib` on binaries and `$ORIGIN` on libraries), multi-version, an
install-name override, and a working non-root Debian example run end to end (`p12-brew.sh`) are in
2k5art3x. Step 0's hard facts here (bwrap 0.13 from source, the read-only-bind mechanic, the
timings) carry over.

Kept open, not closed: the work itself continues as 2k5art3x.
