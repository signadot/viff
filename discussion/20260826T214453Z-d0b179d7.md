HOW TO FILL IN THE 25, and the split question settled. Follows the format proposal above; this is
the half that is actual work.

## First, "25" is the wrong number, and the format above is why

`api.Route`'s own doc already names the ambiguity: "Empty is the fourth case and means nothing
worth naming came back — a route that answers with no body, OR one whose shape is not named yet."
Two opposite facts, printing identically as `{}`. Sorted:

  - **~9 are correctly empty.** The six DELETEs (`deleteEntity` answers 204), `POST
    /tasks/{id}/cancel`, `POST /scope/delete`. There is nothing to fill in; the format should say
    `answers: nothing` and mean it.
  - **1 is free today.** `GET /healthz` answers `{ok, started, head}` out of `Health() map[string]any`.
    Three fields, no tension, give it a struct.
  - **13 are ONE decision**, below.
  - **~3 are server-built documents**: `GET /charter` (root.tony already says it belongs "the day
    one exists") and `GET /schema{,/{name}}`, whose shape is a tony schema.

So the first move is to make `Returns` distinguish "no body" from "not described". It is a small
change to a type that already documents the ambiguity, and until it lands nobody can tell how big
this is.

## go:embed is fenced off from most of this, deliberately

`TestCuratedSetEqualsCustomCodecTypes` holds the curated set equal to the types declaring
`codec=custom`, in BOTH directions, and carries the SAT argument for why: `cur ∧ genOK ∧ ¬curOK`
is satisfiable, so a stale hand-written entry goes on shadowing a now-correct generated one —
"not hypothetical: go-tony fixed three separate defects in one week, and verse-entity and
verse-event were retired BY HAND both times."

So hand-writing definitions for types that do not declare `codec=custom` either fails that test or
means loosening the guard whose failure mode is already written down. `go:embed` is right where
the wire shape genuinely is not the Go shape — which here is `GET /schema`'s own shape, and
little else.

## The 13: split stored from computed

`listGates`, `listResolvers`, `listRunners`, `listSources` and their `{name}` and `/check`
variants all build `[]map[string]any` by hand, and not out of laziness. The row has two
provenances. `listRunners` is the clearest:

```go
rec := map[string]any{"at": …, "name": e.Name, "kind": e.Kind, "url": e.URL}  // STORED
for k, v := range runnerCounts(instances, ref, e.URL) { rec[k] = v }          // computed: store
if probe {                                                                    // computed: network
    reach, why := runner.Probe(e.URL)
    rec["reach"], rec["why"] = reach.String(), …
}
```

SPLIT, and the split is cheap where it counts: **the stored half already exists as a Go type** —
`resolver.Resolver`, `source.Entity`, runner's registration — it is the same thing you PUT, and
`verse data verse:runners:pool:code` already answers it. So that half is GENERATED and cannot
drift. What needs writing is only the VIEW: the listing row.

THE RULE, stated so it does not over-apply: split where a row has TWO PROVENANCES. A wholly
computed answer is just a type — `verse status` has no stored status entity behind it, so
`api.Status` is one named type and correctly so, and `/healthz` will be the same. There is nothing
to separate it from.

Within the computed half there are two kinds, and the difference is worth carrying:

  - **from the store** — `running`/`total`/`lastSpawn`, a walk of task instances. Always present.
  - **by probing** — `reach`/`why`, only under `?probe=true`, and the handler's comment says why it
    cannot be cached: "a reachability column is as of now or it is a cache that can be stale in
    the direction that costs".

`omitzero` carries the second on the wire, but a schema alone cannot say WHY it is optional. Paired
with the `query:` section proposed above it can: `reach` is present iff `probe` was asked for, and
the two sections say that between them. That is the strongest argument yet for putting `query:` in
the format now rather than later.

Precedent already in tree: `verse-runner-status` (kind/resume/dial) is exactly a small derived type
about a runner, used inside `api.Status`.

## Order of work

1. `Returns` distinguishes "no body" from "not described". Everything else is unmeasurable until it does.
2. `/healthz` gets a struct. One route, no decisions.
3. Tag the stored halves for codegen and wire `resolver`, `runner` and `source` into schema.go —
   they are not among the six packages the schema is assembled from today, which is the whole
   reason these types are absent.
4. Write the four view types. This is the decision, and (3) makes it smaller than it looks.
5. `go:embed` for `GET /schema`'s own shape, last, and only there.
