Step 0 committed: **6a4d519c**, reworked in **f33fa6cb** on verse/mcp (`.worktrees/mcp`, local, unpushed). `verse mcp` with `verse_data`; make check and the whole suite green at both.

Decisions taken in the doing:

- **A tool is a call of the API, through the client the CLI builds** (per Scott, 2026-10-21: "using the api with some shared support funcs from the cli, rather than the cli … the cli will change more than the api and with more uncertainty"). 6a4d519c ran the `verse` binary per call with a built argv; f33fa6cb replaces that. What a command and its tool both need is a function both call. For data that is `stateQuery`, which builds the read, and `renderDoc`/`renderPaths`, which write the answer to any writer with filters, format and colour passed in. `printDoc` and `printPaths` are those functions plus what one invocation decided. Each later tool follows the same pattern: find the request and rendering inside the command's run, pull them into functions taking explicit arguments (no `flt`, `trig`, `asOverride` or `cc`), and have the command call them too.
- **The server builds one client at start** (`apiClient()` after flags), so the CLI's transport stamps the version, principal and login's bearer. `skewCheck` now takes the bearer under `bearerMu`, since the server sends requests side by side and the bearer rewrites the tokens file on renewal. `client.GetContext` exists so a call the host cancels ends its request; later tools need the same for POST, PATCH and DELETE.
- **No `--as` on `verse mcp`.** The server acts as whoever `verse` acts as there: the config, the login, `VERSE_USER`. A host that wants another identity sets the environment in its server entry, which is v27eah17's point 2.
- **An answer over `mcpAnswerMax` (64 KiB) is refused** with how to narrow it, and never cut.

Test harness: `mcpSession` (in-memory transports, the client from `apiClient()` at `testAddr`) and `callTool` in `cmd/verse/mcp_test.go`. The tests compare a tool's answer with what the CLI prints for the same read.
